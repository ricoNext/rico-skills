## 文体与基调

- 面向程序员与技术爱好者的**周刊/文摘体**：信息聚合为主，夹叙夹议。
- 语气偏**平实、克制**，但在关键处会用短促感叹或反问抬升情绪（如表达难以置信、无奈、叹服），形成「冷静叙述 + 偶尔抒情」的节奏。
- 常把安全事件、社会新闻写成**有起承转合的故事线**，再收束到对行业或生活的启示。
- 读者假设：能读懂常见技术名词（库名、平台名、协议名），不需要从零科普基础概念。

## 句法与节奏

- 以**中短句**为主，段落不长，阅读负担低；关键数字与影响面会单独成句强调。
- 爱用**枚举推进**（「第一件事/第二件事/第三件事」等）把并列新闻串成一条论证链。
- 解释复杂事件时：**先给结论或定性**，再按时间或因果展开细节。
- 适当插入**引用块**承载当事人自述或媒体报道摘录，正文负责承上启下与点评。
- 过渡常用：「可以看到」「大家要知道」「这让我联想到」「再回到……本身」「下面就是……最精彩的部分」等。

## 词汇与术语

- 技术词汇**自然嵌入**（开源、依赖、令牌、算力、客户端请求等），不堆叠定义式长句。
- 常见衔接：「主要原因是」「原因是」「这意味着」「不知道这是不是……」「据……透露/称/介绍」。
- 评价性用语偏口语但不过分网络化：如「真让人无语」「新鲜的是」「简直……」。
- 产品/机构名称可中英并用，以读者熟悉度为准。

## 段落与篇章结构

- **固定栏目化**：开篇刊物说明 → 若干主题小节（二级标题）→ 常见尾部区块如「文章 / 工具 / 资源 / 图片 / 文摘 / 言论」等 → 「往年回顾」→ 结束标记。
- 每个推荐条目：**标题链接 + 可选语种标注 + 配图 + 一两句提要**；工具/资源类偏「它解决什么问题」。
- 长文议题常用结构：**外链事实 → 配图佐证 → 叙事还原 → 类比或第二案例 → 抽象规律或金句式收束**（常类比到开发规则或生活常识）。
- 言论区：引用 + 破折号署名与身份/出处链接。

## 标点与版式

- 标准 Markdown：**二级标题分节**，列表用有序或无序，`**加粗**` 标出结论句或高危提醒。
- 直接引语用 `>` 引用块；正文与引用分工明确。
- 中文行文中的英文、数字与专名保持**可读间距习惯**（遵循中文排版惯例即可）。

## 开篇与收束

- 开篇常含：**刊物定位**（周期性、内容类型、发布时间）+ **开源/投稿/合作**等元信息（以外链形式呈现）。
- 章节开头可用**一张「封面图」配一句场景说明**，并保留来源标注习惯。
- 收束偏好：**一句话总结趋势或态度**；周刊常用「（完）」作结；「往年回顾」用内链形成时间纵深。

## 禁忌与避免

- 样本中未体现：激烈人身攻击、脏话、长篇说教；若沿用该风格，宜保持**事实来源可指向**（链接、转述），避免无根据断言。
- 避免把档案式写法写成**逐句仿写他人原文**；创作时重结构与方法，不复刻独家措辞长段。
