# 作者行文风格（学习与套用）

## 适用范围与版本说明

- **本版本支持的输入**：
  - 用户在对话中直接给出的**一段或多段纯文本**；和/或
  - 用户给出的**一个或多个 `http://` / `https://` 网页地址**：由 Agent 抓取页面、抽取**正文主内容**后，与纯文本样本一样进入归纳与档案合并流程。
- **本版本暂不实现**：多个本地文件、本地目录的批量导入（可后续扩展）。
- **作者**：可由用户指定显示名；未指定时一律视为 **`default`（默认作者）**。若用户提供多篇网页且未逐篇指定作者，**默认**将本轮从所有 URL 得到的正文**一并**归入当前选定的同一 `author_slug`；若用户声明「某 URL 属于另一作者」，仅为该 URL 归纳并写入对应 slug 的档案（可分多轮执行）。
- **运行时数据位置（重要）**：本 skill 产生的作者档案等文件**一律**写入 **`~/.rico-skills/author-writing-style/profiles/`**（见下文「作者档案目录」），**禁止**向 skill 安装目录（与 `SKILL.md` 同级的 `profiles/`）写入或更新个人行文档案，避免把个人数据混进 skill 仓库或安装包。
- **隐私与内容**：不得把用户正文原文长期完整存入档案（除非用户明确要求留存样例）；档案只存**可复用的风格规范**。

## 作者档案目录（固定路径）

- **目录**：`~/.rico-skills/author-writing-style/profiles/`（将 `~` 展开为用户主目录的绝对路径）。
- **某一作者档案文件**：`~/.rico-skills/author-writing-style/profiles/<author_slug>.md`

在读取或写入前，若 `profiles` 或其上级目录不存在，应**逐级创建**。不在此路径之外保存作者风格档案。

### 与 skill 安装目录的关系

- 随仓库/安装包自带的 `skills/author-writing-style/profiles/` 下文件（若有）**仅可作只读参考**，不得作为运行时写入目标。
- 若用户曾把档案写在安装目录或项目下的其它路径，可提示其**手动迁移**到上述固定目录。

## 作者标识（author_slug）

1. 若用户提供了可用于文件名的英文标识（如 `rico-blog`），直接使用：转小写，将空格改为 `-`，仅保留 `[a-z0-9-]`，连续连字符合并为一条。
2. 若用户只给中文名或其它 Unicode 名：在档案 YAML 的 `author_display_name` 中保留原名；`author_slug` 由 Agent 生成 **ASCII slug**（如拼音、常用英文名、或 `author` + 短哈希），并在首次创建档案时向用户说明该 slug。
3. **`default`**：用户未说明作者时，`author_slug` 固定为 `default`，显示名写作 `默认作者`。

## 模式一：学习并更新行文习惯（建档 / 迭代）

**触发**：用户提供样例文本和/或网页链接，并希望「总结写法」「记录风格」「从网页学文风」「更新某作者的写作规范」等。

### 从网页 URL 获取正文（子流程）

对列表中的每个 URL 依次（或并行，视工具能力）执行：

1. **校验**：仅处理 `http://` 与 `https://`；拒绝或跳过 `file://`、内网未授权地址等可疑目标；用户声明仅供内网调试时除外，但仍须遵守安全与合规。
2. **抓取**：使用当前环境可用的能力获取页面（例如 MCP 网页抓取、`curl`、无头浏览器、或项目内既有「URL 转可读文本」工具）。优先取得**渲染后**与**用户可见**相近的正文；若页面强依赖登录、人机验证或付费墙且无法合法取得正文，如实记录失败原因并中止该 URL。
3. **抽取主内容**：
   - 去除站点导航、页脚、侧栏、评论区、脚本样式块等噪声；保留标题与正文段落。
   - 若存在多篇文章或列表页，**默认**取与当前 URL 最匹配的一篇主文；若明显为目录页，可向用户确认是否抓取子链，或仅基于摘要性文字归纳（并在回复中说明样本偏薄）。
4. **长度与版权边界**：
   - 归纳时只在上下文中保留必要片段长度的原文引用（用于判断句式），**档案中**只写归纳后的**风格规则**，不把抓取到的第三方全文写入 `profiles`。
   - 若站点条款或法律明显禁止自动化抓取，应提示用户改用手动粘贴正文或换用允许的方式。
5. **多 URL**：将各页正文按顺序拼接为内部素材池，或分篇归纳后再合并规则；合并逻辑与单篇相同，注意跨页风格冲突时在档案中写清「不同载体下的差异」。

### 步骤（共用骨架）

1. **确定作者**：得到 `author_display_name`（可选）与 `author_slug`（规则见上）；未指定作者则 `default` / `默认作者`。
2. **读取既有档案**：路径 `~/.rico-skills/author-writing-style/profiles/<author_slug>.md`（`~` 已展开）。若存在，完整阅读其中的规范与「变更记录」。
3. **准备用于归纳的原文素材**（只在本轮分析中使用，**不**整篇写入档案）：
   - **若有用户粘贴的文本**：直接纳入素材池。
   - **若有网页 URL**：执行上文「从网页 URL 获取正文」子流程，将每个成功页面得到的正文纳入素材池；失败 URL 在回复中列明原因，不影响其余 URL 与粘贴文本的处理（除非用户要求全部成功才继续）。
4. **从素材归纳**（只提炼规律；**禁止**把第三方网页全文或长段原文抄入档案），至少覆盖下列维度（无则写「未体现 / 样本不足」）：
   - 文体、语气、读者假设与叙述视角
   - 句子长度、节奏、口语/书面程度
   - 常用衔接、过渡、段落组织方式
   - 词汇偏好、术语、禁用或慎用表达（若可观察）
   - 标点、换行、列表、加粗等版式习惯
   - 开篇/收尾方式、标题层级偏好（若有）
5. **合并更新**：
   - 与旧档案**去重、对齐、消解矛盾**；新样本推翻旧判断时，以新归纳为准并记在变更记录里。
   - 在档案末尾「变更记录」增加一条：日期、本次新增/修正的要点摘要（一两句）；若本轮使用了网页，摘要中注明「来源含网页」及**规范化后的 URL 列表**（勿粘贴整页 HTML）。
6. **写回文件**：保存到 `~/.rico-skills/author-writing-style/profiles/<author_slug>.md`，结构须符合下文「档案模板」；若文件不存在则创建（须先确保目录存在）。
7. **回复用户**：简要说明本次强化了哪些维度、使用了哪些来源（粘贴 / 哪些 URL）、并给出**实际写入的绝对路径**（或从 `~` 起的可读路径）。

### 模式一与模式二的关系

- 模式二**不**主动联网；仅读取已有 `profiles`。若用户希望按「某网页当前文风」改写但未建档，应先走模式一（粘贴文本或 URL）再模式二。

## 模式二：按作者行文习惯改写或生成

**触发**：用户要求按某作者（或默认作者）的既有习惯**改写**给定内容，或**生成**文章/段落。

**步骤**：

1. **解析作者**：未指定则用 `default`。
2. **加载档案**：读取 `~/.rico-skills/author-writing-style/profiles/<author_slug>.md`（`~` 已展开）。若不存在或关键段落大量为「待归纳」且几乎无可用规则：如实告知需先执行**模式一**提供样例；若用户坚持生成，仅基于有限信息给出保守输出，并声明依据不足。
3. **执行创作**：
   - **改写**：在保持用户给定事实与意图的前提下，调整句式、节奏、衔接与版式以贴合档案；不捏造事实。
   - **生成**：主题与要点来自用户指令；风格严格对齐档案；若用户要求字数、体裁、大纲，一并遵守。
4. **输出**：直接给出成品正文；必要时在正文后可附极短的「相对档案的对应说明」（用户不需要则可省略）。

## 档案模板（`profiles/<author_slug>.md`）

新建或重写档案时保持下列结构（可增删子标题，但 YAML 与核心区块建议保留）：

```markdown
---
author_display_name: 显示名或默认作者
author_slug: slug
last_updated: YYYY-MM-DD
---

## 文体与基调

## 句法与节奏

## 词汇与术语

## 段落与篇章结构

## 标点与版式

## 开篇与收束

## 禁忌与避免

## 变更记录

- YYYY-MM-DD：摘要说明
```

## 质量与安全

- **隐私**：不在回复中复述用户样例里的敏感信息；档案只写风格规律。
- **版权与网页来源**：从网页学习时只抽取**可泛化的写作习惯**；不把受版权保护的全文或独创表达整段写入档案。生成与改写不刻意复刻第三方作品的独特表达；用户要求模仿特定真人/名家时，同样只保留结构层面习惯。
- **抓取合规**：遵守站点 robots 提示与用户授权范围；不协助绕过登录、付费或验证码；对明确禁止抓取的站点改为请用户手动粘贴正文。
- **冲突**：用户指令与档案冲突时，以用户**本次明确指令**为准，并可在变更记录中记一笔以便后续迭代。

## 示例（极简）

- 模式一（纯文本）：归纳后写入 `~/.rico-skills/author-writing-style/profiles/default.md`。
- 模式一（网页）：抓取 URL 正文后合并进 `~/.rico-skills/author-writing-style/profiles/default.md`，变更记录中注明 URL。
- 模式二：读取 `~/.rico-skills/author-writing-style/profiles/default.md` 后输出改写稿。
