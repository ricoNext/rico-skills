# 作者行文风格（学习与套用）

## 适用范围与版本说明

- **本版本**：只处理用户在对话中直接给出的**一段或多段纯文本**。不实现：多个本地文件、文件夹、网页地址的批量导入（后续版本再扩展）。
- **作者**：可由用户指定显示名；未指定时一律视为 **`default`（默认作者）**。
- **档案位置**：与本 skill 同目录下的 `profiles/<author_slug>.md`。不得把用户正文原文长期完整存入档案（除非用户明确要求留存样例）；档案只存**可复用的风格规范**。

## 作者标识（author_slug）

1. 若用户提供了可用于文件名的英文标识（如 `rico-blog`），直接使用：转小写，将空格改为 `-`，仅保留 `[a-z0-9-]`，连续连字符合并为一条。
2. 若用户只给中文名或其它 Unicode 名：在档案 YAML 的 `author_display_name` 中保留原名；`author_slug` 由 Agent 生成 **ASCII slug**（如拼音、常用英文名、或 `author` + 短哈希），并在首次创建档案时向用户说明该 slug。
3. **`default`**：用户未说明作者时，`author_slug` 固定为 `default`，显示名写作 `默认作者`。

## 模式一：学习并更新行文习惯（建档 / 迭代）

**触发**：用户提供样例文本，并希望「总结写法」「记录风格」「更新某作者的写作规范」等。

**步骤**：

1. **确定作者**：得到 `author_display_name`（可选）与 `author_slug`（规则见上）；未指定作者则 `default` / `默认作者`。
2. **读取既有档案**：若存在 `profiles/<author_slug>.md`，完整阅读其中的规范与「变更记录」。
3. **从新文本归纳**（只提炼规律，不抄袭存整段原文），至少覆盖下列维度（无则写「未体现 / 样本不足」）：
   - 文体、语气、读者假设与叙述视角
   - 句子长度、节奏、口语/书面程度
   - 常用衔接、过渡、段落组织方式
   - 词汇偏好、术语、禁用或慎用表达（若可观察）
   - 标点、换行、列表、加粗等版式习惯
   - 开篇/收尾方式、标题层级偏好（若有）
4. **合并更新**：
   - 与旧档案**去重、对齐、消解矛盾**；新样本推翻旧判断时，以新归纳为准并记在变更记录里。
   - 在档案末尾「变更记录」增加一条：日期、本次从用户输入中新增/修正的要点摘要（一两句即可）。
5. **写回文件**：保存到 `profiles/<author_slug>.md`，结构须符合下文「档案模板」；若文件不存在则创建。
6. **回复用户**：简要说明本次强化了哪些维度，以及档案路径。

## 模式二：按作者行文习惯改写或生成

**触发**：用户要求按某作者（或默认作者）的既有习惯**改写**给定内容，或**生成**文章/段落。

**步骤**：

1. **解析作者**：同上，未指定则用 `default`。
2. **加载档案**：读取 `profiles/<author_slug>.md`。若不存在或关键段落大量为「待归纳」且几乎无可用规则：如实告知需先执行**模式一**提供样例；若用户坚持生成，仅基于有限信息给出保守输出，并声明依据不足。
3. **执行创作**：
   - **改写**：在保持用户给定事实与意图的前提下，调整句式、节奏、衔接与版式以贴合档案；不捏造事实。
   - **生成**：主题与要点来自用户指令；风格严格对齐档案；若用户要求字数、体裁、大纲，一并遵守。
4. **输出**：直接给出成品正文；必要时在正文后可附极短的「相对档案的对应说明」（用户不需要则可省略）。

## 档案模板（`profiles/<author_slug>.md`）

新建或重写档案时保持下列结构（可增删子标题，但 YAML 与核心区块建议保留）：

```markdown
---
author_display_name: 显示名或默认作者
author_slug: slug
last_updated: YYYY-MM-DD
---

## 文体与基调

## 句法与节奏

## 词汇与术语

## 段落与篇章结构

## 标点与版式

## 开篇与收束

## 禁忌与避免

## 变更记录

- YYYY-MM-DD：摘要说明
```

## 质量与安全

- **隐私**：不在回复中复述用户样例里的敏感信息；档案只写风格规律。
- **版权**：生成与改写不刻意复刻第三方受版权保护作品的独特表达；用户要求模仿特定真人/名家时，只抽取**可泛化的结构习惯**，避免逐句复刻名篇。
- **冲突**：用户指令与档案冲突时，以用户**本次明确指令**为准，并可在变更记录中记一笔以便后续迭代。

## 示例（极简）

- 模式一：「下面是我写的一段周报，帮我记下来以后都按这个写法」→ 更新 `profiles/default.md`。
- 模式二：「用 default 档案里的习惯，把下面这段改得更像我平时写的那样：……」→ 读档后输出改写稿。
