# 作者行文风格（学习与写入）

## 适用范围

- 支持用户在对话中给出的一段或多段纯文本。
- 支持一个或多个 `http://` 或 `https://` 网页地址。
- 暂不批量导入本地文件或目录。
- 用户未指定作者时，使用 `default` 和显示名「默认作者」。
- 多个未单独标注作者的样本归入同一个作者档案。
- 本 skill 只归纳和更新档案；改写或生成由
  **writing-style-apply** 负责。
- 档案只保留可复用规则，不长期保存正文或长段原文。

## 作者档案目录（固定路径）

- 目录：`~/.rico-skills/author-writing-style/profiles/`
- 档案：`~/.rico-skills/author-writing-style/profiles/{author_slug}.md`

将 `~` 展开为用户主目录的绝对路径。读取或写入前，逐级创建不存在的
目录。不得在该路径之外保存作者风格档案。

### 与 skill 安装目录的关系

- `skills/writing-style-learn/profiles/` 中的文件仅可作只读参考。
- 不得把 skill 安装目录作为运行时写入目标。
- 发现旧档案位于其它路径时，提示用户迁移，不擅自移动。

## 作者标识（author_slug）

按以下顺序生成稳定、可重复的标识：

1. 用户未指定作者时，使用 `default`。
2. 用户给出 ASCII 标识时，转为小写，把空格替换为 `-`，仅保留
   `[a-z0-9-]`，合并连续连字符并移除首尾连字符。
3. 用户只给出 Unicode 名称时，优先使用稳定的拼音或罗马化结果；无法
   稳定转换时，使用 `author-` 加显示名哈希的前八位。
4. 清洗结果为空时，使用上述哈希方案。
5. 创建前检查目标文件。若同一 slug 对应不同显示名，先让用户确认。
6. 首次创建时，向用户说明最终使用的 slug。

## 从网页 URL 获取正文

对每个 URL 执行：

1. **校验协议和目标**
   - 仅处理 `http://` 和 `https://`。
   - 拒绝包含用户名或密码的 URL。
   - 默认拒绝回环、私有网段、链路本地地址、云元数据地址及其它非公开
     目标。
   - 检查重定向后的最终目标，防止公开地址跳转到非公开地址。
   - 只有用户明确授权具体内网主机时才访问该主机。
2. **抓取页面**
   - 优先使用能够提取用户可见正文的网页读取工具。
   - 静态读取无法获得正文时，再使用渲染能力。
   - 不绕过登录、验证码、付费墙或站点访问限制。
3. **抽取主内容**
   - 保留标题和正文，去除导航、页脚、侧栏、评论、脚本及样式。
   - 目录页默认只使用当前页面正文；抓取子链接前先征得用户同意。
4. **控制内容边界**
   - 原文只在本轮分析中保留必要片段。
   - 不把网页全文、长段原文或独特表达写入档案。
   - 站点明确禁止自动化访问时，请用户手动粘贴正文。
5. **处理多个 URL**
   - 先逐篇归纳，再合并稳定规则。
   - 不同体裁产生冲突时，记录为「场景差异」，不要强行统一。

## 学习并更新档案

1. **确定作者**
   - 得到 `author_display_name` 和 `author_slug`。
   - 未指定作者时使用 `default` 和「默认作者」。
2. **读取并检查旧档案**
   - 完整读取目标档案。
   - 检查 YAML、slug 与文件名是否一致。
   - 缺少 `schema_version` 的旧档案视为版本 `0`，迁移时保留原有规则。
   - 档案损坏或归属不明确时停止写入，并向用户说明。
3. **准备素材**
   - 将用户粘贴的文本直接纳入本轮素材池。
   - 网页执行 URL 子流程。单个网页失败不影响其它样本，除非用户要求
     全部成功。
4. **归纳规则**
   - 提炼文体、语气、读者假设和叙述视角。
   - 提炼句子长度、节奏、口语或书面程度。
   - 提炼衔接、段落结构、开篇与收束方式。
   - 提炼词汇、术语、慎用和禁用表达。
   - 提炼标点、换行、列表、强调及标题习惯。
   - 每条规则应具体、可执行；避免「表达自然」等空泛描述。
   - 样本不足时明确标注，不根据缺失信息作反向推断。
5. **合并旧规则**
   - 去重并保留未被新样本涉及的已有规则。
   - 单个新样本与旧规则冲突时，优先记录为场景差异或降低置信度。
   - 只有用户明确纠正，或多份新样本形成稳定证据时，才覆盖旧判断。
   - 优先记录稳定规律；只给不确定或易变化的判断标注置信度。
6. **更新元数据**
   - 保留原 `created_at`，更新 `last_updated`。
   - 更新累计样本数量；无法确定历史数量时不得编造。
   - 变更记录写明日期、规则变化及来源类型，不保存正文。
   - 网页来源默认只记录数量。确需记录地址时，只保留
     `scheme + host + pathname`，移除凭据、查询参数和 fragment。
7. **验证并写回**
   - 使用下方模板，保持 `schema_version: 1`。
   - 验证 YAML 可解析、slug 与文件名一致、核心区块齐全。
   - 确认没有敏感信息、长段原文或不必要的来源地址。
   - 确认生成的 Markdown 符合 markdownlint 规则。
   - 先写同目录临时文件；验证通过后再替换目标文件。
   - 写入失败时保留旧档案。
8. **回复用户**
   - 简述本次强化或修正的维度及使用的来源类型。
   - 给出实际写入路径。
   - 网页失败时列明 URL 和原因，但不暴露其中的敏感参数。

## 档案模板（`profiles/<author_slug>.md`）

新建或迁移档案时保留下列 YAML 字段和核心区块。章节没有可靠结论时，
写「样本不足」，不要留空或编造。

```markdown
---
schema_version: 1
author_display_name: 显示名或默认作者
author_slug: slug
created_at: YYYY-MM-DD
last_updated: YYYY-MM-DD
sample_summary:
  text_count: 0
  webpage_count: 0
---
```

## 质量与安全

- 不在档案或回复中复述样本里的敏感信息。
- 只抽取可泛化的写作习惯，不保存受版权保护的长段表达。
- 遵守站点访问限制和用户授权范围。
- 不协助绕过登录、付费或验证码。
- 用户本次明确指令高于档案规则。
- 对特定真人或作者只归纳高层特征，不复刻独特表达。
